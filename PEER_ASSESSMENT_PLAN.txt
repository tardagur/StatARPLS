Where to type each command: lines marked [R] go in the R console;

    (knitr and rmarkdown are needed to build the vignette and to run
    devtools::check()).
  - Git, for the clone step (Step 4).
  - A C++ compiler toolchain, because the package contains compiled code:
    Rtools on Windows, Xcode command line tools on macOS, build-essential
    on Linux.
  - Please record your versions and include them in your report:

    [R]  R.version.string
    [R]  packageVersion("devtools")
    [R]  packageVersion("pak")

  - The author tested with: R 4.5.2 (2025-10-31, Windows), devtools 2.5.2,
    pak 0.11.1.

    install.packages(c("pak", "devtools", "knitr", "rmarkdown"))

Step 2 [R] - Install StatARPLS from GitHub:

    pak::pak("tardagur/StatARPLS")

  Notes:
  - Installation compiles C++ code and can take a minute or two.
  - pak asks "Do you want to continue (Y/n)?". Type Y.
  - This install does not build the vignette; see Step 7.
  - If R says the package is "in use and will not be installed", restart R
    and run the command again before calling library(StatARPLS).

Step 3 [R] - Load the package:

    library(StatARPLS)

Step 4 [shell] - Clone the repository so the test suite can be run from

    cd StatARPLS

2. OVERVIEW OF COMPONENTS
============================================================

All functions return, or act on, one S3 class: "StatARPLSResult".

2.1  StatARPLSResult()            R/constructors.R
     Validated constructor for the result object (ten core fields).

2.2  fit_arpls()                  R/fit-arpls.R
     Fits an ARPLS baseline for a user-supplied lambda. The linear
     solve runs in a compiled Rcpp/RcppArmadillo engine
     (src/arpls_solver.cpp); a pure-R reference engine is kept for tests.

2.3  gcv_select_lambda()          R/parameter-selection.R
     Chooses lambda automatically by generalised cross-validation, with
     the effective degrees of freedom estimated by Hutchinson's
     stochastic trace estimator. Warns if the selected lambda is the
     smallest value in the grid (GCV can under-smooth reweighted fits).

2.4  bootstrap_baseline_uncertainty()   R/parameter-selection.R
     Moving-block residual bootstrap giving a baseline "stability band"
     (default B = 200). The band measures sampling stability at fixed
     lambda; it is NOT a measure of the baseline's bias.

2.5  S3 methods                   R/methods.R
     print(), summary() (with print.summary()), plot(), predict(),
     compare() (with print.compare()).

Quick example to try (a synthetic spectrum with one peak):

    set.seed(1)
    n <- 300
    wavenumber <- seq(400, 1800, length.out = n)
    baseline_true <- 2 + 0.002 * wavenumber
    signal <- baseline_true + 3 * exp(-((wavenumber - 1000) / 40)^2) +
      rnorm(n, sd = 0.05)

    fit  <- gcv_select_lambda(signal, wavenumber, seed = 1)
    boot <- bootstrap_baseline_uncertainty(fit, B = 50, seed = 2)

    print(boot)
    summary(boot)
    plot(boot)
    plot(boot, show_band = FALSE)
    predict(boot, newdata = c(500, 900, 1500))
    compare(fit, boot)

What to check: the red baseline lies under the peak and follows the slow
upward drift; the shaded band is very thin (it is drawn but may be barely
visible at this scale); with show_band = FALSE the band AND its legend
entry both disappear; predict() returns three values.

Note on compare(fit, boot): the two rows carry different kinds of band
(fit has the provisional +/- 1.96 SD band, boot has the bootstrap band),
so their mean_band_width values are not directly comparable. The other
columns (lambda, iterations, convergence) are.

3. ADVERSARIAL TESTING AND ERROR HANDLING EXPECTATIONS
============================================================

Each case below should now fail (or warn) with a clear, package-level
message, not a low-level R error. Please record the text you actually see.

3.1  Mismatched lengths
    fit_arpls(signal = c(1, 2, 3, 4, 5), wavenumber = c(1, 2, 3))
    Expected: "`wavenumber` must be the same length as `signal`."

3.2  Malformed stability_bounds matrix
    StatARPLSResult(signal = 1:5, wavenumber = 1:5, baseline = 1:5,
      corrected = 1:5, residual_variance = 1,
      stability_bounds = matrix(0, nrow = 5, ncol = 3), lambda = 100,
      n_iter = 5L, converged = TRUE, call = quote(f()))
    Expected: error about stability_bounds needing 5 rows and 2 columns.

3.3  Non-positive lambda
    (same as 3.2 with stability_bounds = cbind(rep(-1, 5), rep(1, 5))
     and lambda = -5)
    Expected: "`lambda` must be a single strictly positive finite number."

3.4  Non-scalar converged flag
    (same as 3.3 with lambda = 10 and converged = c(TRUE, FALSE))
    Expected: "`converged` must be a single logical value."

3.5  Non-numeric signal            (previously a KNOWN GAP; now handled)
    fit_arpls(signal = c("a", "b", "c"), wavenumber = 1:3)
    Expected: "`signal` must be a numeric vector."

3.6  Non-finite signal             (new; from peer review)
    sig <- rnorm(60); sig[30] <- NA
    fit_arpls(sig, 1:60, lambda = 1e5)
    Expected: error naming the non-finite position(s), e.g.
    "`signal` contains non-finite values (NA/NaN/Inf) at position(s): 30".

3.7  Too few points / empty input  (new; from peer review)
    fit_arpls(signal = c(1, 2))
    StatARPLSResult(signal = numeric(0), wavenumber = numeric(0),
      baseline = numeric(0), corrected = numeric(0),
      residual_variance = NA_real_,
      stability_bounds = matrix(numeric(0), 0, 2), lambda = 100,
      n_iter = 1L, converged = TRUE, call = quote(f()))
    Expected: both error with "... must have at least 3 points". Empty
    and very short results are not valid objects.

3.8  Noise-free flat spectrum      (new; from peer review)
    fit_arpls(rep(5, 50), 1:50, lambda = 1e4)
    Expected: no error; converged = TRUE; baseline equal to about 5.

3.9  Wavenumber axis               (new)
    fit_arpls(rnorm(50), wavenumber = 50:1)         # descending
    Expected: error saying the axis must be strictly increasing, with a
    suggestion to sort and interpolate (stats::approx()).
    fit_arpls(rnorm(50), wavenumber = c(1:25, 27:51))  # uneven spacing
    Expected: a warning about uneven spacing, not an error.

3.10 compare() with a non-fit      (new; from peer review)
    compare(fit, "not_a_fit")
    Expected: error saying all objects passed via ... must be of class
    StatARPLSResult (no silently dropped row, no mislabelled table).

3.11 predict() out-of-range, both methods   (new; from peer review)
    below <- min(fit$wavenumber) - 1
    predict(fit, below, method = "linear", rule = 2)
    predict(fit, below, method = "spline", rule = 2)
    Expected: both return the first baseline value (fit$baseline[1]).
    predict(fit, below, method = "linear", rule = 1)  -> NA
    predict(fit, below, method = "spline", rule = 1)  -> NA plus a warning.

3.12 Smallest-lambda warning       (new)
    gcv_select_lambda() warns when the selected lambda is the smallest
    value in lambda_grid, because GCV can under-smooth reweighted fits.
    This is exercised by the automated suite (test-noise-and-axis.R).
    It is NOT reliably reproducible by hand on a smooth synthetic
    spectrum, where GCV tends to prefer large lambda, so a reviewer who
    does not see the warning on the quick example above has not found a
    bug. (It fired on two of four real textile spectra during the
    author's testing; see Section 6.)

6. KNOWN LIMITATIONS
============================================================

 - GCV can pick the smallest lambda in the grid on some real spectra, so
   the baseline follows the peaks. The package warns when this happens.
   Inspect plot() and consider a larger minimum lambda, for example
   lambda_grid = 10^seq(4, 9, length.out = 11).
 - The stability band measures sampling stability at a fixed lambda, not
   bias. A thin band does not prove the baseline is correct.
 - ARPLS can absorb very broad peaks into the baseline (a known property
   of the algorithm).
 - The linear solve is dense, so spectra with several thousand points are
   slow (automatic lambda selection at about 1,900 points takes a couple
   of seconds; the bootstrap takes longer). A sparse/banded solver is
   future work.
